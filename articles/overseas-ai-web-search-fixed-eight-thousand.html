检索结果很短，为什么小模型仍按八千个输入 token 计？

OpenAI 的现行网页搜索是两笔账：搜索动作按调用另计一次，从索引取回、再送进模型的内容按该模型的输入价计。gpt-4o-mini 和 gpt-4.1-mini 在非预览工具上，这笔内容不是按取回了多少字来量，而是每次调用固定 8000 个输入 token。屏幕上的回答可以只有一句。把 search_context_size 调到 low，文档写明它不设定确切的 token 数，脚注里的这块也不因此变小。非推理模型上的预览工具走另一行，搜索内容 token 不计。单价留在价目页。

核验清单

  • ✓先数 action.type 为 search 的次数。指南把工具调用费写在搜索动作上。引用条数和来源条数都不是这次调用的次数。
  • ✓gpt-4o-mini 和 gpt-4.1-mini 配非预览的 web_search，搜索内容按每次调用固定 8000 个输入 token 计。结果再短也不缩成实际字数。
  • ✓search_context_size 的 low、medium、high 不设定确切 token 数。调到 low 不改上面那块 8000。
  • ✓非推理模型的 web_search_preview 不另计搜索内容 token，调用行也和现行工具不同。推理模型的预览行仍计搜索内容 token。
  • ✓Responses 里 tool_choice 为 auto 时，搜索可以不发生。Chat Completions 的搜索模型会先搜再答。单价以价目页为准。

1. 调用是一笔，检索内容是另一笔

价目页把现行网页搜索写成一行，括号里写明包含图像搜索：一次调用的费用，再加上搜索内容 token，搜索内容按所选模型的价格计。同一张表把预览工具拆成两行。推理模型的预览行同样是调用费加上按模型价计的搜索内容 token。其他模型的预览行是另一档调用费，并且写明搜索内容 token 免费。具体单价以这一页当时的数字为准，本文不把某一天的美元标成长期牌价。

页下的说明把搜索内容 token 定义成：从搜索索引取回、连同你的提示一起送进模型、用来生成回答的那些 token。它们是输入侧的内容，不是第三种商品名。内置工具用掉的 token 按所选模型的 token 价计。所以一次成功的搜索，至少要对上两列：搜索动作带来的调用，以及送进模型的检索内容。你自己的提示词、模型写出的回答，仍按这次请求自己的输入和输出计。8000 不是整次请求的全部，它也替代不了调用那一列。

固定块只写给两个模型。网页搜索指南所指向的价目脚注写的是：gpt-4o-mini 和 gpt-4.1-mini 使用非预览的网页搜索工具时，搜索内容 token 按每次调用固定 8000 个输入 token 计。脚注用的是 input tokens，没有把这块写成缓存输入。缓存折扣是价目上另一列，这句脚注没有把它套到这块固定输入上。别的模型没有这句。它们的搜索内容仍按该模型的输入价计，数量随取回的内容走，不能把 8000 抄过去。图像搜索在现行这一行的名称里已经包含，不要再按旧表加一笔图像搜索调用。

2. 回答很短，low 也缩不了这块

屏幕上那句回答是 message 里的正文。固定块计的是送进模型的检索内容，不是正文有多短。一次调用只带回几个词，在这两个小模型上，搜索内容这一列仍是 8000 个输入 token。把「结果看起来很小」当成「检索内容很少」，对的是别的模型上按实量计的那一列，对不上这句脚注。

指南对 search_context_size 的定义是：它控制在生成回答之前，有多少网页搜索结果的上下文提供给模型。low 适合只要几个细节的查询，medium 是均衡的默认，high 用于答案可能需要更多细节的时候。紧接着的一句是：这个设置不设定确切的 token 数，也不保证来源或引用的条数。所以把旋钮拧到 low，改变的是提供给模型的上下文档位，不是把脚注里的 8000 改成一个更小的整数。在 gpt-4o-mini 和 gpt-4.1-mini 的非预览工具上，计费块是按次固定的。low 不能拿来当省 token 的开关。

引用也不是次数。输出里的 url_citation 标注给出被引用的 URL、标题和位置。指南写明，来源的数量常常多于引用的数量。一次 action.type 为 search 的动作，可以带出多条引用。对这两个小模型，那仍是一次调用、一块 8000。反过来，一次响应里如果出现两个搜索动作，指南把工具调用费写在搜索动作上，脚注写的是 per call。两个搜索动作是两次调用，也是两块 8000，不是「一次对话所以只计一块」。数的时候数搜索动作，不数引用，也不数来源。

3. 没搜成，就不要按搜成了去加

Responses 里，tool_choice 为 auto 时，搜索是可选的。指南写明，必须搜的时候用 required，或指定网页搜索这项工具。没有发出搜索动作，那句「搜索动作产生工具调用费」就没有落点。不要因为请求里挂了工具，就按一次网页搜索去估。用户自定义函数的 schema 即使没被调用也会占输入，见函数没被点到，为什么整份定义还按输入扣？。托管的网页搜索不是那份 schema。

Chat Completions 的搜索模型是另一条路径。迁移表写明：这些模型会在回答之前先搜索；Responses 里的搜索才是一项工具。走 Chat Completions 搜索模型，没有「这次模型决定不搜」这一种省法。指南还列出 gpt-5-search-api 的上下文窗口是 200k，并且这条路径不支持 Responses 上的域名过滤、完整来源列表、实时访问开关和返回 token 预算。8000 的脚注没有写到这个模型上。对它要按它自己的搜索内容用量和调用行去对，不要把小模型的固定块搬过来。

推理模型上还有 open_page 和 find_in_page。指南把「产生工具调用费」这句只写在 search 后面，没有把同一句抄到打开页面和页内查找上。它也没有写这两种动作免费，更没有写它们各自再加一块 8000。8000 的脚注对象是那两个小模型的非预览网页搜索，而打开页面、页内查找写的是推理模型才支持。对账时按输出里的 action.type 分开，不要把搜索动作的句子套到另外两种动作上。

4. 预算、窗口和已经关掉的模型

return_token_budget 只作用于 Responses 上、GPT-5 及之后推理模型的托管网页搜索。default 和省略这个参数是同一行为。unlimited 去掉默认的返回 token 预算，指南写明它会增加延迟和费用。同一段也写明：它不改变搜索的上下文窗口，并且不适用于非推理的网页搜索、旧的 Search API、容器里的网页搜索、Chat Completions 的搜索模型，以及 web_search_preview。gpt-4o-mini 和 gpt-4.1-mini 的那块 8000 因此换不掉。把预算设成 unlimited，不会让小模型改按实量计，也不会让非推理模型突然套上这套预算。

Responses 的网页搜索上下文窗口上限是 128k，即使底层模型的窗口更大。这是窗口，不是一笔已经计好的 128k token，也不是折扣。超出窗口的内容不在这次搜索的上下文里。不要把 128k 加进 8000 再估一笔。

external_web_access 设为 false 时，工具只用缓存或索引结果，不抓实时页面。不设的时候默认是 true，也就是实时访问。指南没有为离线模式另开一行更低的价格。预览工具会忽略这个参数，并按 true 来行为。想用关掉外网来少计那块 8000，文档里没有这个对应关系。

迁移表写明，gpt-4o-search-preview 和 gpt-4o-mini-search-preview 已弃用，并在 2026-07-23 关闭。今天已经过了这个日期。新的调用再按这两个模型名去对账，对的是迁移表里已经关掉的路径。它建议迁到 Responses 的 web_search，若必须留在 Chat Completions，则用 gpt-5-search-api。同一张表写 o4-mini 已在 2026-10-23 关闭。仍在用 gpt-5 的集成，网页搜索要求推理力度高于 minimal。这些是路径是否还在，不是把固定块扩大到所有模型。

文件搜索的存储和调用是另一种工具。当天没人搜，向量库超过免费额度仍按天计，见文件没人搜，向量库为什么还在按天扣？。网页搜索的一次调用不是向量库的一天。代码容器按会话分钟计、有五分钟下限，见代码只跑了一小会儿，为什么容器至少按五分钟计？。模型既搜了网页又跑了代码，两行分开加，不要因为搜过网页就再加一个容器下限。国内另一家的搜索是模型费之外再扣一笔，口径不同，见模型账单对上了，搜索费为什么还在扣？，不要把 8000 写进那本账。

5. 充值改不了这块固定输入

对账按六列走。第一列是工具：现行 web_search，还是 web_search_preview。第二列是模型：是不是 gpt-4o-mini 或 gpt-4.1-mini，并且用的是不是非预览工具。第三列是搜索动作的次数，只数 action.type 为 search 的，不数引用。第四列是搜索内容：这两个小模型按次固定 8000 个输入 token，其他模型按实量、按该模型输入价，非推理模型的预览行这一列为零。第五列是这次请求自己的提示和输出，它们在固定块之外。第六列是路径：Responses 在 auto 下可以不搜，Chat Completions 的搜索模型会先搜再答。

给账户准备额度，发生在这些列扣款之前。链上把稳定币换成能付进账户的资产，不会把一句很短的回答收成按字计费，也不会把 low 变成一块更小的输入。需要这一步时，可以用无需注册、非托管的 AllSwap 完成链上兑换。兑换成功只说明资产换了手。调用次数、那块 8000，以及预览行是否免掉搜索内容 token，仍按这次实际发出的搜索动作计。
