解析按页扣完了，抽取为什么还是另一本账？

阿里云百炼 ParseX 把 Parse 和 Extract 分成两本用量。图文按实际处理的页数计，文本容器按字数折成页，音视频按秒。赠送额度只在首次开通时发一次。新文档直接抽取只扣抽取额度，单价里已经包含解析，不要再加一笔。别的工具里转过格式，不算可复用的解析结果。工作流里的文档解析节点目前不计费，接到它后面的大模型节点仍按 token 计。

核验清单

  • ✓打开这一次的任务记录，看它走的是解析还是抽取，以及处理了多少页或多少秒。资源管理器里的页数对不上，先查是不是超长图被切开，或文本按 2000 字折成了页。
  • ✓如果是新文档直接抽取，只看抽取额度减了多少。解析赠送额度不该因此减少。单价已经包含解析，不要再加一笔解析费。
  • ✓要复用结果，确认它是 ParseX 自己的图文 ParseResult，而且仍在常见问题页写的 7 天保留期内。音频、视频，或在别的工具里转过的文件，不算这一档。
  • ✓工作流里的文档解析节点按该页所说目前不计费。顺着连线看后面的大模型节点，摘要用掉的输入和输出仍按那个模型的 token 计。
  • ✓字段是 missing 或 conflict 时，先看任务状态是不是 success。完整评估过 Schema 仍可以成功。空字段不等于这次没计费。

1. 解析和抽取不是同一列页数

计量与计费开头就把两本账分开：Parse 和 Extract 分项记录用量。图文按页，音频和视频解析按秒。PDF、PPT 和图片按实际处理页数计，图片按页计，超长图片会切割。Word、表格、Markdown、纯文本、HTML、电子书按文本量除以 2000 折成页。音视频按实际处理时长，以秒计。一份很长的 txt 可以变成很多页，一张竖长截图也可以被切成多页。账单上的页数对不上你在文件夹里看到的页数，常常是这个口径，不是任务把页数记错了。

首次开通 ParseX 的账号获赠图文解析 3000 页、字段抽取 3000 页、视频解析 100 小时、音频解析 100 小时。规则写明只在首次开通时赠送一次，不按日或按月重新发放。额度用尽后自动按量收费。新文档直接抽取只抵扣抽取赠送额度，不占用解析赠送额度。页面举的例子是：直接抽取一份 10 页的新文档，抽取额度够用时扣 10 页抽取额度，解析额度不减少。解析额度还在，不能读成抽取也不该付钱。两本赠送账没有加成一本。

新文档直接抽取的单价已经包含解析，不需要再加一次解析费用。使用可复用解析结果再抽取，是另一档。页面写明，「已解析」指本次抽取实际复用了 ParseX 的解析结果。文件在其他工具中处理过，不属于这一价格场景。在本地先转成 Markdown 再送进来，不能拿去套「已经解析过，所以只付抽取」的那一档。具体单价以计量页为准，这里不把某一天的数字写成长期价格。

2. 抽取只认图文结果

支持的文件与限制把能力边界写在表上。Parse 支持文档、图片、扫描件、表格、文本，也支持音频和视频。Extract 只支持图文，只能复用有效的图文 ParseResult。复用是为了避免对同一文件再解析一次。音频或视频的解析结果不能用于抽取。常见问题用同一句话收束：Extract 当前仅支持图文文件，也只能复用图文 ParseResult。把一段会议录音解析完，再拿那个结果去抽字段，对不上这条边界。

同一页 FAQ 写，当前可复用的图文 ParseResult 保留 7 天。结果下载地址可能更早过期，以接口返回的过期时间为准。下载链接打不开，不等于那份结果还在 7 天窗口里；链接还能下，也不要把保留期改成你记得的另一个天数。对不上时看任务记录和错误码，不要用控制台界面上的别的标识去猜哪一笔还能复用。

体验页当前限制为单文件不超过 200 MB，FAQ 写明这不等于 API 上限。限制页的表是：文档、文本、网页、电子书，API 1 GB、控制台上传 200 MB；图片两边都是 20 MB；音频 API 2 GB、控制台 200 MB；视频 API 10 GB、控制台 200 MB。体验页传不上去，不代表接口也拒。接口传进去了，也不要用体验页的 200 MB 去估这一笔会折成多少页。

3. 工作流那一格目前不计，模型仍计

文档解析节点第一段写，该节点暂不计费。它按文件类型输出结构化变量。选「其他」时给出 layout 数组和 markdown 内容，选 Excel 时给出单元格。页面自己举的用法是：先解析文档，再由大模型节点生成摘要。节点这一格目前不进 ParseX 的按页账。大模型节点吃到的是解析出来的正文，按那个模型的输入和输出 token 计。把「工作流里解析是免费的」读成「整条摘要链路免费」，会漏掉后一格。

这一格和 ParseX 也不是同一个产品表面。节点页写的限制是单文件不超过 150 MB、页数不超过 1.5 万页，只支持单文件，不支持列表。用网页 URL 而不是文件直链会解析失败。页面说网页 URL 不是有效的文档文件。失败了，这一格仍按该页所说暂不计费。你如果改走 ParseX 的接口重试，那一笔就回到按页或按秒的账上。两条路径的「解析」字样一样，计费开关不一样。

4. 知识库时钟和空字段不要并进去

知识库从创建成功起按规格小时走，对话窗口关掉也不停，那是另一篇。向量化、排序和问答模型另计 token。ParseX 的页和秒不包含那口时钟，知识库的小时费也不包含 ParseX 的解析页。对话停了，两口表可以各自还在。联网搜索按次另计，是搜索那篇。免费额度用尽后转按量，是模型免费额度那篇。ParseX 的赠送是开通时一次，不按日刷新，和模型推理的免费 token 不是同一个余额。

FAQ 写明 Parse 和 Extract 都是异步任务。提交响应返回 biz_id，结果响应是 processing、success 或 failed。只有状态为 success 才能获取最终结果。Extract 返回 missing 或 conflict 不代表任务失败。只要系统完整评估了整个 Schema，状态仍可以是 success。missing 是没找到字段，conflict 是原文有冲突候选。对账时不要把「字段空了」当成「这次没计费」，也不要把 success 当成「每个字段都抽到了」。

文件、配置、任务和结果按 Workspace 隔离。切了工作空间看不到原来的任务，不代表那笔用量消失。用量页看的是一段时间内各类处理量，任务记录看的是某一次用了什么能力、处理了多少。两处对的是不同问题，不能用其中一处的空白去否定另一处的数字。

5. 充值缩不短这些页

对账按这一次处理的四列走。第一列是 Parse 的页或秒，包括超长图切开的页，以及文本按 2000 字折出来的页。第二列是 Extract：新文档直接抽取只动抽取额度，单价已含解析，不要再加一笔；复用只认 ParseX 自己的图文结果，而且有保留期。第三列是工作流文档节点，目前不计，但后面的模型 token 仍计。第四列是知识库规格小时和检索模型，跟页数不是同一个开关。四列都落在各自的用量上，不能收成「文件已经传上去了，所以应该只付一次」。

给阿里云账户充值，发生在这些列扣款之前。链上把稳定币换成能充进账户的资产，不会把一张长图合成一页，不会让抽取额度去抵解析，也不会让工作流后面的模型调用变成免费。需要这一步时，可以用无需注册、非托管的 AllSwap 完成链上兑换。兑换成功只说明资产换了手。页数和秒数仍按这次实际处理的量计。
