接口停了，专属部署为什么还在按小时扣？

按 token 的在线推理可以不调用不计费。百炼专属部署和火山方舟的模型单元、TPM 保障包买的是时长或容量：状态变成运行中、或者下单成功之后，时钟就在走。删 API Key 停的是意外调用，不是这口表。吞吐预留默认还会把超出的请求再按 token 计一笔。

ipfsWeb · AI服务指南编辑部 · 发布于 2026-10-15 15:07:00 北京时间（UTC+08:00）

核验清单

  • ✓打开百炼专属部署或火山接入点，看状态是不是仍为运行中或健康。运行中就在计时长，token 调用次数为 0 不能证明没在扣。
  • ✓按计费方式停表：百炼按时长的后付费要下线部署；预付费吞吐预留要下线后再退订。删 API Key 只防止意外的 token 调用。
  • ✓看溢出策略。默认「自动溢出」时，响应头 x-dashscope-ptu-overflow: true 表示这笔已离开预留价，按模型调用的 token 价另计。
  • ✓火山模型单元在接入点详情页退订才停表。没开智能唤醒与休眠时，最小单元数不能为 0，缩到最小仍然在计费。
  • ✓欠费不要混用两家规则。火山按 token 欠费超过约 1 分钟会关停；模型单元和 TPM 保障包欠费后大约 2 小时仍可用，而且继续扣。

1. 调用次数归零，只证明 token 那一列停了

火山方舟把在线推理分成三列，写在模型服务计费说明里。按 token 后付费：不调用不计费。TPM 保障包和模型单元：按购买时长计费，不调用也会收费。前一列看的是 prompt_token 和 completion_token。后两列看的是你买下的额度还在不在、单元还退没退订。财务若只导出「模型调用 token」，会把一台还在跑的专属算力看成零消费。

百炼这边，账单与停计费说明写得更直：模型部署按使用时长计费，状态变为运行中就开始收，不依赖 API 调用。没人打这只模型，只要部署还是运行中，费用继续走。训练与部署计费的问答补了一刀：部署中、欠费、部署失败不计部署费；运行中才计。包月预付费从运行中开始消耗包月时间。所以「部署失败」和「部署成功但没人用」不是同一笔账。失败不计；成功闲置，计。

这和知识库空闲计费不是同一口表。知识库扣的是规格小时、向量和排序。这里扣的是为某个模型独占或预留的推理容量。对话窗口关了、脚本停了、甚至 Key 删了，容量时钟可以还在走。

2. 吞吐预留买的是容量，用不用都按购买量收

吞吐预留写明：创建成功即开始计费。预留容量内的调用不另收 token 费，容量费按购买量计，不因实际用量减免。利用率低不是折扣。你买了 1 万 TPM 却只打了几百，账单仍按那 1 万算。自动续费默认开启，到期前 1 天扣款，当天 8:20 到 20:00 最多试 4 次。关掉得在到期前，不是到期当天才发现又被续上一天。

超出容量不是「免费排队」。默认策略是自动溢出：超出的请求降级成该模型的标准按量，服务不中断，不再走预留价。响应头会出现 x-dashscope-ptu-overflow: true。改成「仅使用预留容量」，超出返回 429，超出部分不另收费。还有一条容易漏：自动溢出下，单次输入超过模型最长输入 token，这一笔也会转成按量。预留没满，超长输入仍然可以在 token 账单上再出现一行。

退订不是按剩余天数原价退。已使用不超过 30 天，已结算部分按 1.2 倍惩罚系数；超过 30 天按 1.0。用得越久，剩余越少，退款可以是 0。账单页对预付费吞吐预留的停表顺序是：先下线已部署模型，再在退订管理里退实例。只删 API Key，停的是按 token 的意外调用，不停按时长或按容量的那一列。

到期之后到底停不停，两页官方说明并不一样。训练与部署计费页写：预付费到期后延后 2 小时停止服务，停止后再保留 14 小时才释放。吞吐预留常见问题写：到期后立即停用并释放，专属模型 Code 失效，不可恢复。对账不要用日历上的 23:59 代替控制台状态。Code 还在、状态仍是运行中，就还没停；Code 已经失效，调用失败也不等于时长费已经结清。后付费欠费时，部署计费页写资源不再可用且不计费，缴清后恢复。这和下一节火山的欠费宽限不是同一条规则。

3. 火山的表从下单成功起算，退订才停

模型单元概述把后付费写成按实际购买时长、精确到秒，不足一秒按一秒。购买后持续计费，停止的动作是在接入点详情页退订，不是把调用量打到零。文档里的例子：16:00 下单成功，18:20:31 退订成功，计费时长是 2 小时 20 分 31 秒。中间如果一次请求都没有，时长照算。出账按小时，通常在计费周期结束后 1 到 2 小时。16:00 到 17:00 的账，大约 18:00 到 19:00 才出现。当小时账单还是空的，不能当成已经停表。

欠费规则从 2025-07-16 起改过，而且把模型单元和 TPM 保障包排除在外。按 token 的服务，欠费超过约 1 分钟就关停（仍有资源包的，用完资源包再关）。按小时后付费的模型单元和 TPM 保障包，欠费后还有大约 2 小时的「欠费-关停」阶段，具体以通知为准。这 2 小时里资源仍可用，费用仍在产生。确定不用，要去接入点详情页退订，不能干等关停。预付费按月购买后按自然日生效；到期时间是到期自然日加 1 天的中午 12 点，回收再加 24 小时。文档举例：4 月 13 日上午 9 点买一个月，到期是 5 月 14 日中午 12 点，回收是 5 月 15 日中午 12 点。回收期结束就不能续费，得新建推理接入点。未到期退订有惩罚系数，不能按剩余时间全额退；模型单元按实例组绑定，续费和退订要一起发起。

弹性伸缩也停不了「最小还大于零」的那一档。创建模型单元写明：没开智能唤醒与休眠时，最小单元数不能为 0。缩到最小，时钟还在。智能唤醒与休眠目前是邀测。开了之后才能把最小设为 0，无流量后缩到零才停止计费；从 0 拉回 1 要冷启动，可能要几分钟。最小为 0 的部署，7 天没有流量会被自动删除。没开这项功能就去把副本数调到最小，省下的不是整口表。

4. 三件看起来像停机的事，都不是退订

第一件是把业务流量切走。按 token 的列会归零，时长列不会。百炼按量付费还是预占加月结：调用后几分钟出账，不等于次月初才扣的那笔已经结清，更不等于部署时长费不存在。免费额度、资源包、节省计划进的是按量抵扣顺序，抵不了已经按容量或按时长买下的那一列。欠费期间，百炼即使还剩免费额度也不能继续按量调用，要先结清。这救不了仍在运行中的部署，也解释不了「token 是 0、总账还在涨」。

第二件是删 API Key。账单页把两条路拆开：按 token 的后付费，下线部署，或删 Key 防止意外调用；按模型单元或算力时长的后付费，要下线部署；预付费吞吐预留，下线之后还要退订。删 Key 是一把锁，不是退订按钮。Key 没了，别人偷调不了，你买的单元还在。

第三件是看 429 就重试。仅使用预留容量时，429 是容量墙，重试不会把这笔变成按量，也不会把容量时钟停掉。自动溢出时，请求是成功的，贵的是它已经离开预留价。日志里只存了 HTTP 200，看不出头里的 x-dashscope-ptu-overflow。把溢出流量当成「还在预留额度里」，月结时才发现 token 列和容量列各有一笔。

5. 给云账户充值，停不了已经跑起来的单元

对账列四列。第一列是部署或接入点状态：运行中、健康、调度中、已下线，还是已退订。第二列是计费方式：按 token、吞吐预留，还是模型单元，溢出策略是自动还是 429。第三列是到期、自动续费和回收时刻，百炼两页文档对「到期后是否立刻停」写法不一致，以控制台为准。第四列是欠费规则落在哪一类：火山按 token 大约 1 分钟关停，模型单元和保障包大约再扣 2 小时；百炼后付费部署欠费后，文档写不再可用且不计费。

给云账户充值是第五本账。链上把稳定币换成能充进云账号的资产，发生在阿里云或火山引擎入账之前，不改变部署状态，也不等于模型单元已经退订。需要这一步时，可以用无需注册、非托管的 AllSwap 完成链上兑换。兑换成功只说明资产换了手。运行中的专属部署该下线还得下线，该退订还得退订。
