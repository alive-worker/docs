Why does a two-minute video bill by sampled frames?

Alibaba Cloud Model Studio does not settle vision understanding by the length of the clip. The model samples frames, then converts those frames into tokens. fps is one frame every 1/fps seconds, from 0.1 to 10, and the default is 2.0, which is one frame every half second. When the file has enough frames, the sample floor is 4. Setting fps to 0.1 does not go below that. The published estimate takes the frame count, divides by 2, rounds up, multiplies by the resized height and width, and adds 2. Those 2 are the vision markers for the whole clip, not 2 per frame. More frames also shrink the pixel budget of each frame, so twice the frames is not twice the tokens. This API says it does not understand the soundtrack, so there is no audio-token column. The code is an estimate. The API usage is the bill. Unit prices stay on the console.

1. Two minutes decides whether the file is accepted. Frames decide the tokens

The image and video understanding page bills the total of input and output tokens. Prices are on the Model Studio console. Input tokens are text tokens plus the tokens converted from images or video. Output tokens are the text the model generates. This article does not freeze one day's yuan rates.

The estimator states the order for a video file: sample frames, then total the tokens of those frames. "Two minutes" is not 120 billing units. Duration shows up under the limits, and it decides whether the file is accepted. The qwen3.8, qwen3.7, qwen3.6, and qwen3.5 series run from 2 seconds to 2 hours. qwen3-vl-plus runs from 2 seconds to 1 hour. Other open Qwen3-VL models run from 2 seconds to 20 minutes. Open Qwen2.5-VL and QVQ run from 2 seconds to 10 minutes. Other models run from 2 seconds to 40 seconds. A file shorter than its floor never enters this API. It is not accepted and then billed as two seconds of tokens. A file longer than its ceiling is rejected by the same limit. It is not trimmed to the ceiling and then priced by the second.

The sampling rate is fps. The guide says one frame is taken every 1/fps seconds, the range is 0.1 to 10, and the default is 2.0. The default is one frame every half second. Fast motion wants a higher fps. A static or long video wants a lower one. Those sentences are about detail and efficiency. On the bill, what changes is the number of frames. When fps is omitted, the estimator also uses 2.0. Two minutes at 2.0 is on the order of 240 frames, before the cap and the pixel budget. Do not write 120 seconds down as the token count.

2. Four frames is the floor. The fifth frame opens another pair

The estimator sets the minimum sample at 4, then rounds that minimum up to a multiple of 2. Four is already even, so the floor stays 4. The frame count starts as duration times fps, then it is clamped between the minimum, the maximum, and the file's own frame count. When the file has enough frames, an fps of 0.1, the bottom of the range, still does not sample fewer than 4. The seconds that were not sampled are not a zero-price duration. They never became frames. If the file itself has fewer than 4 frames, the sample cannot exceed that total. The API does not invent the missing frames.

The token is not a price per frame. The video estimate is: divide the frame count by 2, round up, multiply by the resized height over 32 and the resized width over 32, then add 2. Four frames are 2 pairs. Five frames round up to 3 pairs. The extra frame opens another pair. It does not add half of a pair. The final 2 are vision_bos and vision_eos once for the clip, not 2 on every frame. A still image is resized height times width, divided by the pixels per token, plus the same 2. See How Many Tokens Does One Image Cost in Vision APIs? Video pairs the frames before it spends the pixels. Do not estimate the clip as one image's tokens times the number of seconds.

max_frames is the sample cap. When the fps count would pass it, the system samples uniformly inside the cap. The guide says this parameter is available only in the DashScope SDK. The OpenAI-compatible examples pass video_url and fps. They do not list max_frames on that path. On the compatible API, do not assume a max_frames field you added has already capped the frames. The sample code uses 2000 as its maximum and tells you to change it for the model. Image-list limits are a different table: qwen3.8, qwen3.7, qwen3.6, and qwen3.5 allow up to 8000 images, qwen3-vl-plus up to 2000, other open Qwen3-VL, Qwen2.5-VL, and QVQ up to 512, and other models up to 80. The minimum is 4 in each row. Do not copy the sample's 2000 onto every video file.

3. More frames make each frame's pixel budget smaller

The per-frame pixel cap is not a fixed width and height. The estimator takes the smaller of the model's per-frame pixel cap and the total pixel budget divided by the frame count and multiplied by 2, and it will not go below about 1.05 times the pixel floor. As the frame count rises, the budget left for each frame shrinks, and the picture is scaled tighter. Twice the frames is not twice the tokens. A larger source file does not buy a better reading either. The guide says a larger video will not be understood better, because the model resizes through max_pixels and min_pixels. Sending a 4K file unchanged is not a purchase of more usable pixels.

The constants depend on the model. The sample sets Qwen3-VL-Plus's per-frame cap at 640 times 32 times 32, and the total pixels at 131072 times 32 times 32. The same comment sets other models at 768 times 32 times 32, and 65536 times 32 times 32. The image section splits pixels per token again: qwen3.8, qwen3.7, qwen3.6, qwen3.5, and Qwen3-VL use 32 by 32. QVQ and other Qwen2.5-VL models use 28 by 28. The printed video formula divides by 32. If the model is in the 28 group, do not paste that divisor onto it. The fps and the pixel caps in the estimate have to match the parameters of the request. The page says the code is only an estimate. Usage in the API response is the amount that was used.

One request can carry up to 64 videos. Each video is sampled on its own. The number 64 is not 64 copies of a free frame floor. The floor belongs to each video that is sampled. A file that is too large is a different problem from the token formula. Public URLs, Base64, and local paths have different size caps, and the page says those limits depend on the model. Buying a higher plan or moving to another model version does not raise them. Compress the file, or pass a public URL. Model Studio cannot read an internal OSS address. The call returns InvalidParameter, and the message says the multimodal content failed to download. The file never went in. That is not a token estimate of a two-minute clip.

4. An image list, the soundtrack, and thinking are not the clip length

A video can also arrive as an image list you already sampled. The list needs at least 4 images. The estimator written for that list takes the count you pass and the size of one frame. Its parameters do not include fps. The guide separately says that fps on an image list tells the model the interval between frames, so it can read order and duration, and that this applies to Qwen3.6, Qwen3-VL, and Qwen2.5-VL. It does not describe that fps as a second sampling pass. Four images are four images, paired and resized. They are not a two-minute clip sampled again. The original duration is not an input of that function.

The soundtrack is not billed here, because it is not understood. The limits say the API does not understand audio inside a video file. There is no audio-token column to add beside the frames. A different translation API splits video_tokens and audio_tokens. That split is not this page's formula. Do not copy the translation sampler over. Generating a picture or a video is another ledger too. A reference video's input side is cut by a five-second pool. See Why does a 30-second reference bill from a five-second pool? Those seconds are a generation unit. Here, a second only decides which frames are taken.

Thinking is output, not a frame. The billing section says that in thinking mode the reasoning is counted as output tokens, and that if thinking mode emits no reasoning, the call is priced as non-thinking. That sentence does not add the chain of thought to the frame count, and it does not promise a block of reasoning text on every thinking call. How a reasoning model's chain is billed is a separate page. See Is DeepSeek-R1 reasoning_content Chain-of-Thought Billed? Neither page is a way to change fps.

The batch discount does not change the sample either. The production section says large, non-realtime jobs can use the OpenAI-compatible Batch file input, on some models only, processed asynchronously, at a 50 percent cost discount. The discount sits on that path's fee. It does not turn 4 frames into 2, and it does not divide by 2 a second time. The free quota names Beijing and Singapore: 1 million tokens for vision models, for 90 days from opening Model Studio or from model approval. The page does not publish that million for other regions, and it does not publish one million per video. After a timeout, the header x-dashscope-partialresponse: true means already generated text was returned. The billing section does not give that partial reply a zero row. Text that was generated is still output. Sending it back as a prefix is a new request, and that text enters the input again.

5. A top-up does not change the sample, or the floor of four

Reconcile in six columns. First, whether the file is accepted: duration, size, and format against that model's limits. An internal address fails the download. Second, the sample: fps defaults to 2.0 and runs from 0.1 to 10. When the file is long enough, the floor is 4 frames. max_frames is written for the DashScope SDK, and past the cap the sample is uniform inside the cap. Third, the shape of the tokens: divide the frame count by 2, round up, multiply by the resized width and height for that model, and add 2. Use 32 or 28 for the series you called. Do not copy the Qwen3-VL-Plus pixel constants onto another model. Fourth, frames push back on pixels: more frames mean a smaller budget per frame, and a larger source is not more tokens. Fifth, the other objects: an image list bills the count you passed, this API has no soundtrack column, reasoning counts as output only if it was emitted, and the 50 percent batch discount stays on the path that states it. Sixth, usage: the code on the page is an estimate. The usage in the response is this call's number. Check the free quota only if the region is Beijing or Singapore.

Funding the account happens before those columns settle. Swapping stablecoins on-chain into assets that can be paid in does not turn two minutes into 120 tokens, and it does not make an fps of 0.1 sample fewer than 4 frames. When you need that swap, AllSwap does it without an account and without custody. A completed swap only means the asset changed hands. How many frames were sampled, how many pairs that made, and how far each frame was scaled, still follow the frames this call actually took and the usage the API returned.
