Why does a short search still bill 8,000 input tokens?

OpenAI's current web search is two charges. A search action is its own tool call. The tokens retrieved from the index and fed in with the prompt bill at the chosen model's rates. On gpt-4o-mini and gpt-4.1-mini, with the non-preview tool, that content is not measured by how short the page looked. Each call bills a fixed block of 8,000 input tokens. The answer on screen can be one sentence. Setting search_context_size to low does not set an exact token count, and it does not shrink the block. Preview search on non-reasoning models is a different row, and that row does not bill search content tokens. Unit prices stay on the pricing page.

Check before you reconcile

  • ✓Count actions whose type is search. The guide attaches the tool-call cost to search actions. Citations and sources are not the call count.
  • ✓gpt-4o-mini and gpt-4.1-mini with non-preview web_search bill search content as a fixed 8,000 input tokens per call. A short result does not shrink that to the words you saw.
  • ✓search_context_size values low, medium, and high do not set an exact token count. Low does not change the 8,000 block.
  • ✓web_search_preview on non-reasoning models does not bill search content tokens, and its call row is not the current tool's row. Preview on reasoning models still bills search content tokens.
  • ✓In the Responses API, tool_choice auto can skip search. Chat Completions search models search before they answer. Unit prices stay on the pricing page.

1. The call is one charge. The retrieved text is another

The pricing page puts current web search on one row, and the row name includes image search: a per-call charge, plus search content tokens billed at the chosen model's rates. The same table splits the preview tool. Preview on reasoning models is again a call charge plus search content tokens at model rates. Preview on other models is a different call row, and that row says search content tokens are free. The dollar figures on that page are the prices to reconcile against. This article does not freeze one day's numbers into a standing rate.

The note under the table defines search content tokens as tokens retrieved from the search index and fed to the model alongside the prompt, so the model can generate an answer. They are input. They are not a third product name. Tokens used for built-in tools are billed at the chosen model's per-token rates. A search that ran therefore has at least two columns: the call that belongs to the search action, and the retrieved content that was fed in. The prompt you wrote and the answer the model wrote still bill as this request's own input and output. The 8,000 is not the whole request, and it does not replace the call.

The fixed block is written for two models only. The pricing footnote the web search guide points at says: for gpt-4o-mini and gpt-4.1-mini with the non-preview web search tool, search content tokens are billed as a fixed block of 8,000 input tokens per call. The footnote says input tokens. It does not call the block cached input. Cached input is a separate column on the price table, and this sentence does not apply that discount to the block. Other models do not get the sentence. Their search content still bills at their own input rates, by the amount retrieved. Do not copy 8,000 onto them. Image search is already inside the current row's name. Do not add a second image-search call from an older reading of the table.

2. A short answer does not shrink the block, and neither does low

The sentence on screen is the text inside the message. The fixed block bills the retrieved content that was fed to the model, not how short that sentence was. A call that comes back with a few words still bills 8,000 input tokens of search content on these two models. "The result looked small" matches the variable column on other models. It does not match this footnote.

The guide defines search_context_size as how much context from web search results is made available to the model before it generates a response. Low is for a lookup that needs only a few details, medium is the balanced default, and high is for an answer that may need more detail. The next sentence says the setting does not set an exact token count, and does not guarantee a number of sources or citations. Turning the knob to low changes which tier of context is offered. It does not rewrite 8,000 into a smaller integer. On gpt-4o-mini and gpt-4.1-mini with the non-preview tool, the billed block is fixed per call. Low is not a token-saving switch for that block.

Citations are not calls. A url_citation annotation carries the URL, the title, and the location of a cited source. The guide says the number of sources is often greater than the number of citations. One action whose type is search can carry many citations. On these two models that is still one call and one block of 8,000. The other way around: if one response emits two search actions, the guide attaches the tool-call cost to search actions, and the footnote says per call. Two search actions are two calls, and two blocks of 8,000. They are not "one conversation, so one block." Count search actions. Do not count citations, and do not count sources.

3. If search did not run, do not add it as if it had

In the Responses API, tool_choice auto makes search optional. The guide says to use required, or a specific web search tool choice, when search must run. If no search action was emitted, the sentence that search actions incur a tool-call cost has nothing to attach to. Do not estimate a web-search call just because the tool was listed on the request. A function schema you defined can still bill as input when the function never runs. That column is The Tool Never Ran. Its Schema Still Billed. Hosted web search is not that schema.

Chat Completions search models are a different path. The migration table says those models always search before responding, while Responses search is a tool. On the Chat Completions search path there is no saving that comes from the model deciding not to search. The guide also lists gpt-5-search-api with a 200k context window, and that path does not support the Responses controls: domain filters, the full source list, the live-access switch, or the returned-token budget. The 8,000 footnote does not name this model. Reconcile it from its own search-content usage and its own call row. Do not carry the mini-model block across.

Reasoning models can also emit open_page and find_in_page. The guide attaches the tool-call cost sentence only to search. It does not copy that sentence onto opening a page or searching inside a page. It also does not say those two actions are free, and it does not say each one adds another block of 8,000. The 8,000 footnote is about the two mini models on the non-preview web search tool. Opening a page and finding in a page are described as supported on reasoning models. Split them by action.type in the output. Do not lay the search sentence on the other two actions.

4. The budget, the window, and the models that have shut down

return_token_budget applies only to hosted Responses web search on GPT-5 and later reasoning models. default is the same behavior as omitting the parameter. unlimited removes the default returned-token budget, and the guide says it can increase latency and cost. The same section says it does not change the search context window, and it does not apply to non-reasoning web search, legacy Search API paths, container web search, Chat Completions search models, or web_search_preview. The 8,000 block on gpt-4o-mini and gpt-4.1-mini is therefore not something this parameter replaces. Setting the budget to unlimited does not make the mini models bill by actual size, and it does not put the budget on a non-reasoning model.

The Responses web search context window is limited to 128k, even when the underlying model has a larger window. That is a window. It is not 128k tokens already billed, and it is not a discount. Content past the window is not in this search's context. Do not add 128k on top of 8,000 and call that an estimate.

Setting external_web_access to false keeps the tool on cached or indexed results and skips a live fetch. The default, when you omit it, is true, which is live access. The guide does not publish a cheaper row for the offline mode. Preview tools ignore the parameter and behave as if it were true. Turning live access off is not a documented way to shrink the 8,000 block.

The migration table says gpt-4o-search-preview and gpt-4o-mini-search-preview are deprecated and shut down on 2026-07-23. That date has passed. Reconciling a new call against those model names is reconciling a path the table lists as closed. The recommended path is Responses web_search, or gpt-5-search-api if the integration has to stay on Chat Completions. The same table says o4-mini shut down on 2026-10-23. Integrations still on gpt-5 need reasoning effort above minimal before web search runs. Those sentences are about which path is still open. They do not extend the fixed block to every model.

File-search storage and file-search calls are a different tool. A store can bill by the day when nobody searched, once it is past the free allowance. That is Nobody Searched. The Store Still Bills. A web search call is not a vector-store day. A code container bills by session minutes, with a five-minute floor, in Why does a short code run bill five container minutes? If the model searched the web and also ran code, add the rows separately. Do not add a container floor because a web search happened. A domestic vendor's search charge, beside the model bill, is The Model Bill Matches. Search Still Charges. Do not write 8,000 into that ledger.

5. A top-up does not resize the block

Reconcile in six columns. First, the tool: current web_search, or web_search_preview. Second, the model: whether it is gpt-4o-mini or gpt-4.1-mini, and whether the tool is the non-preview one. Third, the number of search actions, counting only action.type search, not citations. Fourth, search content: a fixed 8,000 input tokens per call on those two models, variable input on other models, and zero on the non-reasoning preview row. Fifth, this request's own prompt and output, which sit outside the block. Sixth, the path: Responses with auto can skip search, and Chat Completions search models search before they answer.

Funding the account happens before those columns settle. Swapping stablecoins on-chain into assets that can be paid in does not turn a one-line answer into billing by the word, and it does not turn low into a smaller input block. When that swap is the step you need, AllSwap does it without an account, and it is non-custodial. A completed swap only means the asset changed hands. The call count, the 8,000 block, and whether the preview row waives search content tokens still follow the search actions that were actually emitted.
