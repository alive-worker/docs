Why Connecting MCP Servers Burns 50k Tokens Before You Ask

2026-11-27 23:03:51 · 8 min read

Connecting multiple MCP servers injects 50k+ tokens of tool schemas before your first prompt. Learn how deferred loading, truncation, and sampling cut bills.

Verification Checklist (4 Audits Before Enabling MCP)
  • ✓Measure empty-chat baseline input_tokens: Send a one-word greeting after wiring up your MCP servers and inspect usage logs. Any baseline above 10,000 tokens signals eager schema bloat.
  • ✓Verify deferred loading (Tool Search / defer_loading): Once your toolset exceeds 10 tools, keep only 3–5 core tools always loaded and defer the rest for on-demand discovery.
  • ✓Enforce hard byte/row caps on MCP tool outputs: Confirm SQL, DOM snapshot, and log-query servers truncate and paginate payloads server-side before returning them into conversation history.
  • ✓Audit capabilities.sampling approvals: Ensure untrusted third-party MCP servers cannot silently invoke sampling/createMessage against your client API key without human approval or token caps.

1. The Hidden Cost of "Connect Everything via MCP"

The Model Context Protocol (MCP) makes wiring external tools into AI clients almost effortless. With a few lines of JSON, Claude Code, Cursor, or custom agents can simultaneously control GitHub, PostgreSQL, Playwright, Slack, Jira, and local filesystems.

Yet once teams move from demos to daily production usage, two symptoms appear together: a trivial one-line prompt bills 40,000 to 70,000 input tokens, and the model paradoxically becomes worse at choosing the right tool. Engineers call this the MCP Context Tax—the inevitable side effect of eager schema preloading combined with unpruned multi-turn tool loops.

2. Three Multipliers Behind a 50k-Token Baseline

When an MCP host connects to servers, it fetches each server's tools/list catalog containing tool names, prose descriptions, and nested JSON parameter schemas. Under naive eager loading, every single schema is injected into the prompt prefix on every turn:

  • Multiplier 1: Static Tool Schema Avalanche: A feature-rich GitHub or Playwright MCP server exposes 20–30 tools, consuming 10,000–15,000 tokens on its own. Connecting five servers easily surpasses 90 tools and 55,000–72,000 input tokens before the user types a word—while degrading tool-selection accuracy once active tools exceed 30–50.
  • Multiplier 2: Quadratic O(N²) Payload Replay: Many open-source MCP servers return raw SELECT * JSON dumps, full accessibility DOM trees, or entire PR diffs. Once a 15,000-token tool output lands in chat history, it gets re-billed on turn 2, turn 3, and turn 10, pushing sessions into higher long-context pricing tiers.
  • Multiplier 3: Dynamic Tool Order Busts Prompt Caching: If a server reconnects, refreshes auth, or reorders its tool array dynamically, even a single shifted byte invalidates prefix-based Prompt Caching—forcing your entire 50k-token schema block to re-bill at full non-cached rates.

3. The Overlooked Billing Backdoor: MCP Sampling

Most teams only monitor client-to-server tool calls, overlooking MCP's reverse channel: Sampling (sampling/createMessage). By specification, Sampling allows an MCP server to ask the host client to run LLM completions on its behalf, enabling server-side agent loops without the server owning its own API keys.

While useful in trusted internal environments, exposing auto-approved capabilities.sampling to third-party MCP servers creates an invisible billing vector: a single tool call can silently fan out into 5 or 10 nested LLM completions charged directly to the host's API key, often hidden from the primary chat transcript.

4. Eager Preloading vs. Deferred Loading (Tool Search)

Modern tool orchestration—exemplified by Anthropic's Tool Search and defer_loading: true—replaces blanket preloading with on-demand discovery:

Dimension Default Eager Preload Deferred Loading + Tool Search
Baseline Context 50–100 full schemas (~55k–72k tokens) Search tool + 3–5 core tools (~500–2,000 tokens)
Input Token Cost Pays every turn for dozens of unused tools Expands only 2–4 matched tools (~85% baseline reduction)
Routing Accuracy Drops noticeably beyond 30–50 active tools Focused candidate set improves argument & tool accuracy
Prompt Cache Health Any server reconnect can bust the whole prefix Stable minimal prefix preserves cache breakpoints

5. Four Production Fixes to Eliminate the MCP Tax

1. Enable defer_loading: true Above 10 Tools

Keep only your 3–5 highest-frequency tools always loaded, defer everything else, and apply consistent server prefixes (github_, pg_, slack_) so regex or BM25 tool search retrieves the right subset cleanly. Never mark the Tool Search tool itself as deferred.

// Production MCP deferred-loading pattern
const tools = [
  { type: "tool_search_tool_bm25", name: "tool_search" }, // Always loaded
  ...coreTools.map(t => ({ ...t, defer_loading: false })), // 3-5 frequent tools
  ...mcpTools.map(t => ({
    ...t,
    name: `${t.serverName}_${t.name}`, // Predictable namespace for search
    defer_loading: true                // Hidden until matched on demand
  }))
];

2. Enforce Server-Side Truncation and Cursors

Place a hard cap (e.g., 4,000 characters or 50 rows) inside your MCP gateway. When exceeded, return a compact preview plus truncated: true and a pagination cursor so the model queries precisely instead of flooding the context window.

3. Split MCP Profiles by Workflow and Sort Tools Deterministically

Do not mount browser automation and billing tools inside a pure code-review profile. Keep per-workflow profiles lean and sort tool definitions alphabetically so prompt caches stay warm across reconnects.

4. Gate Sampling with Human Approval and Hard Token Caps

Disable sampling by default for external MCP servers. For internal servers that require it, enforce strict per-call max_tokens limits and rate caps inside the host client.

7. Frequently Asked Questions (FAQ)

Q1: Does Prompt Caching make a 50k-token MCP tool block harmless?

A: No. Cache writes still carry a 1.25x–2x surcharge whenever TTLs expire, and even discounted cached tokens still dilute the model's attention window—causing wrong tool selections and extra retry turns that erase the discount.

Q2: Can we trim verbose open-source MCP tool descriptions without forking every server?

A: Yes. A thin local MCP gateway can intercept tools/list responses and strip repetitive examples or boilerplate notes, often shrinking tool schema token footprint by 30%–45% with zero loss in accuracy.
